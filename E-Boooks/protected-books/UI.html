User Interface Design and Accessibility

Learn the fundamentals of user interface design and web accessibility to create attractive, user-friendly, and inclusive websites.

Designing for Web Accessibility

Web accessibility means designing websites and applications so that people with disabilities can perceive, understand, navigate, and interact with digital content.

Accessible web design considers the needs of people with visual, hearing, physical, and cognitive disabilities.

The World Wide Web Consortium (W3C), through its Web Accessibility Initiative (WAI), provides guidance for creating websites that are easier for everyone to use.

Why Web Accessibility Matters

  • Improves usability for people with disabilities.
  • Supports users who rely on assistive technologies.
  • Makes website navigation easier to understand.
  • Improves readability across different devices.
  • Helps developers follow accessibility guidelines.

Learning Objectives

  • Understand the importance of accessible web design.
  • Apply appropriate color contrast.
  • Communicate information without relying on color alone.
  • Design recognizable interactive elements.
  • Create consistent website navigation.
  • Use accessible labels and feedback messages.
  • Organize content using headings and spacing.
  • Design layouts for different viewport sizes.
  • Provide alternatives for images and media.
  • Provide controls for automatically playing content.

These recommendations help developers work toward the Web Content Accessibility Guidelines (WCAG), but they do not represent every accessibility requirement.

Provide sufficient contrast between foreground and background

Text must have enough contrast against its background so that users can read it comfortably.

This applies to text displayed on solid backgrounds, images, gradients, buttons, and other interface elements.

Insufficient contrast can make content difficult to read, especially for people with low vision or difficulties distinguishing colors.

What Is Contrast Ratio?

Contrast ratio measures the difference in relative luminance between two colors. A higher contrast ratio generally indicates a greater difference between the colors.

WCAG Contrast Requirements

Text Type WCAG AA Minimum
Normal text 4.5:1
Large text 3:1

These are WCAG minimum contrast requirements for applicable text. Large text generally means at least 18-point regular text or 14-point bold text. Logos and incidental text have exceptions.

Example: Poor Contrast

.poor-contrast {
    color: #cccccc;
    background-color: #ffffff;
}

Light gray text on a white background may be difficult for many users to read.

Example: Improved Contrast

.good-contrast {
    color: #202b40;
    background-color: #ffffff;
}

Dark text on a light background provides stronger visual separation.

Important Design Practices

  • Check text contrast against background colors.
  • Check text placed over images and gradients.
  • Test button labels and other interface text.
  • Consider users who need different brightness levels.
  • Use contrast-checking tools when evaluating colors.

Don't use color alone to convey information

Color can help communicate meaning, but it should not be the only way users receive important information.

Some users cannot distinguish certain colors. Others may use grayscale displays or assistive technologies that do not communicate visual color differences.

Example: Required Form Fields

A form that identifies required fields only by displaying their labels in red may be difficult for some users to understand.

Better Approach

Use text or symbols together with color to communicate the requirement. 

<label for="email">
    Email (required)
</label>

<input
    type="email"
    id="email"
    name="email"
    required
>

Example: Error Messages

<p class="error-message">
    Error: Please enter a valid email address.
</p>

The word "Error" communicates the message even when the user cannot distinguish the text color.

Charts and Graphs

Charts should use labels, patterns, numbers, or other identifiers in addition to color.

Recommended Practices

  • Use text labels alongside color indicators.
  • Use symbols to identify required fields.
  • Add labels or patterns to charts.
  • Provide descriptive error messages.
  • Do not describe an option only by its color.

Ensure that interactive elements are easy to identify

Interactive elements such as links, buttons, and form controls should be visually distinguishable from ordinary content.

Users should be able to recognize which elements can be selected, clicked, or activated.

Different Interaction States

  • Default: The normal appearance.
  • Hover: When a pointer is positioned over an element.
  • Focus: When an element receives keyboard focus.
  • Active: When an element is being activated.

Accessible Link Styling

.accessible-link {
    color: #24427f;
    text-decoration: underline;
}

.accessible-link:hover {
    text-decoration-thickness: 2px;
}

.accessible-link:focus-visible {
    outline: 3px solid #3157a4;
    outline-offset: 3px;
}

.accessible-link:active {
    color: #17315f;
}

Why Keyboard Focus Matters

Some people navigate websites using a keyboard rather than a mouse.

When users press the Tab key, the currently focused element should have a visible indication.

Example: Focus Indicator

button:focus-visible {
    outline: 3px solid #3157a4;
    outline-offset: 3px;
}

A visible outline helps keyboard users identify which control is currently active.

Important Practices

  • Make links visually distinct from ordinary text.
  • Provide visible keyboard focus indicators.
  • Use consistent button and link styles.
  • Support mouse, keyboard, and touch interactions.
  • Use descriptive names for interactive controls.

Provide clear and consistent navigation options

Website navigation should be predictable and easy to understand.

Navigation menus should use consistent names, styles, and positions across related webpages.

Why Consistent Navigation Matters

Consistent navigation helps users understand where they are and how to move between different pages.

Common Navigation Methods

  • Main navigation menus
  • Website search
  • Site maps
  • Breadcrumb navigation
  • Clear page headings

Example: Navigation Menu

<nav aria-label="Main navigation">
    <ul>
        <li><a href="index.html">Home</a></li>
        <li><a href="books.html">Books</a></li>
        <li><a href="about.html">About</a></li>
        <li><a href="contact.html">Contact</a></li>
    </ul>
</nav>

Breadcrumb Navigation

Breadcrumbs show the user's location within the website structure. 

<nav aria-label="Breadcrumb">
    <ol>
        <li>
            <a href="index.html">Home</a>
        </li>

        <li>
            <a href="books.html">Books</a>
        </li>

        <li aria-current="page">
            Web Accessibility
        </li>
    </ol>
</nav>

The aria-current="page" attribute identifies the current page within the breadcrumb navigation.

Recommended Practices

  • Keep navigation placement consistent.
  • Use familiar and descriptive navigation labels.
  • Provide more than one way to find pages when applicable.
  • Use headings and breadcrumbs as orientation cues.
  • Help users identify their current location.

Ensure that form elements include clearly associated labels

Every form field should have a clear, descriptive label that explains what information the user must enter.

Labels should be positioned close to their corresponding form controls.

Recommended Label Positioning

In left-to-right languages, labels are usually placed above or to the left of text input fields.

Checkbox and radio button labels are commonly placed to the right of their controls.

Example: Associated Form Label

<label for="full-name">
    Full Name:
</label>

<input
    type="text"
    id="full-name"
    name="full_name"
>

How It Works

The label's for attribute matches the input's id. This creates a programmatic association between the label and the control.

Checkbox Example

<input
    type="checkbox"
    id="agree"
    name="agree"
>

<label for="agree">
    I agree to the terms and conditions.
</label>

Why Labels Are Important

  • Help users understand what information is needed.
  • Support screen readers and other assistive technologies.
  • Make form controls easier to activate.
  • Reduce confusion and input errors.

Placeholder text should not be the only label for an input because it may disappear when users enter information.

Provide easily identifiable feedback

Websites should clearly communicate the results of user interactions.

Feedback may confirm that an action was completed, explain an error, or notify users about changes to the webpage.

Examples of Feedback

  • Successful form submission
  • Incorrect login information
  • Missing required fields
  • Invalid email addresses
  • Successful profile updates

Example: Error Message

<div class="form-error" role="alert">
    <strong>Please correct these errors:</strong>

    <ul>
        <li>Enter a valid email address.</li>
        <li>A message is required.</li>
    </ul>
</div>

Example: Success Message

<p role="status">
    Your message has been submitted successfully.
</p>

The role="status" attribute can help assistive technologies announce a dynamically updated status message.

Styling Feedback Messages

.form-error {
    padding: 15px;
    border: 2px solid #b42318;
    border-radius: 8px;
    background-color: #fff1f0;
    color: #7a1712;
}

.form-success {
    padding: 15px;
    border: 2px solid #18794e;
    border-radius: 8px;
    background-color: #e8f7ee;
    color: #14532d;
}

Error and success messages should include descriptive text rather than relying on background color alone.

Recommended Practices

  • Use clear and understandable messages.
  • Explain which fields need correction.
  • Provide useful suggestions when possible.
  • Make important feedback visually noticeable.
  • Ensure dynamic feedback can be announced accessibly.

Use headings and spacing to group related content

Headings and whitespace help users understand how webpage content is organized.

Related information should appear close together, while separate sections should have enough spacing to distinguish them.

Why Content Organization Matters

  • Makes webpages easier to scan.
  • Reduces visual clutter.
  • Helps users recognize related information.
  • Supports clearer reading and navigation.

Example: Structured Content

<section>

    <h2>Account Information</h2>

    <p>
        Manage your personal information.
    </p>

    <h3>Profile Details</h3>

    <p>
        Update your name and contact details.
    </p>

    <h3>Security Settings</h3>

    <p>
        Manage your password and login settings.
    </p>

</section>

CSS Spacing Example

.content-section {
    margin-bottom: 30px;
    padding: 20px;
}

.content-section h2 {
    margin-bottom: 15px;
}

.content-section p {
    line-height: 1.7;
    margin-bottom: 16px;
}

Important Practices

  • Use meaningful headings.
  • Maintain a logical heading hierarchy.
  • Group related content visually.
  • Use consistent spacing.
  • Avoid unnecessarily crowded layouts.

Create designs for different viewport sizes

Websites should remain usable across different screen sizes, including desktop computers, tablets, and smartphones.

Responsive design also benefits users who enlarge webpage content using browser zoom.

Responsive Design Considerations

  • Adapt navigation to available space.
  • Maintain readable text sizes.
  • Avoid unnecessarily long lines of text.
  • Rearrange content when screen space changes.
  • Keep important information accessible.

Example: Responsive Grid Layout

.responsive-layout {
    display: grid;
    grid-template-columns: 1fr 1fr;
    gap: 20px;
}

@media (max-width: 768px) {
    .responsive-layout {
        grid-template-columns: 1fr;
    }
}

Example Explained

On wider screens, the content appears in two columns.

When the viewport width becomes 768 pixels or smaller, the layout changes to one column.

Viewport Meta Tag

<meta
    name="viewport"
    content="width=device-width, initial-scale=1.0"
>

This meta tag belongs in the HTML document head and helps mobile browsers display responsive layouts at the intended viewport width.

Readable Text

.readable-content {
    max-width: 70ch;
    line-height: 1.6;
    margin-inline: auto;
}

The ch unit can help limit the width of text blocks, improving readability.

Include image and media alternatives in your design

Images, audio, videos, charts, and other non-text content may require accessible alternatives.

These alternatives help users access information when they cannot see or hear the original content.

Common Media Alternatives

  • Alternative text for informative images.
  • Captions for videos.
  • Transcripts for audio content.
  • Audio descriptions for important visual information.
  • Text labels alongside icons.
  • Descriptions for complex charts and graphs.

Example: Alternative Text

<img
    src="images/library.jpg"
    alt="Books arranged on shelves in a library"
>

The alt attribute provides a text alternative describing the image's meaningful content.

Example: Decorative Image

<img
    src="images/decoration.svg"
    alt=""
>

Decorative images that do not communicate meaningful information can use an empty alt attribute.

Example: Video Captions

<video controls width="500">

    <source
        src="videos/tutorial.mp4"
        type="video/mp4"
    >

    <track
        kind="captions"
        src="captions/tutorial-en.vtt"
        srclang="en"
        label="English"
    >

</video>

The track element allows a video to provide captions from a WebVTT file.

Example: Audio Transcript

<audio controls>
    <source
        src="audio/lesson.mp3"
        type="audio/mpeg"
    >
</audio>

<p>
    <a href="lesson-transcript.html">
        Read the audio transcript
    </a>
</p>

Important Design Considerations

  • Reserve space for captions and media controls.
  • Provide visible transcript links.
  • Use text with icons when necessary.
  • Include descriptions for complex visual information.
  • Coordinate with content authors and developers.

Provide controls for content that starts automatically

Automatically playing animations, videos, audio, and image carousels can make websites difficult for some users to navigate.

Users should be able to control content that begins playing or moving automatically.

Examples of Automatically Starting Content

  • Auto-playing videos
  • Background audio
  • Animated banners
  • Image sliders
  • Automatic carousels

Why User Controls Matter

Automatically moving content may distract users or interfere with reading and concentration.

Automatically playing audio may also interfere with screen reader output.

Recommended Controls

  • Play
  • Pause
  • Stop
  • Mute or volume controls
  • Manual slide navigation

Example: Video with User Controls

<video controls width="500">

    <source
        src="videos/introduction.mp4"
        type="video/mp4"
    >

    Your browser does not support video.

</video>

The controls attribute displays the browser's built-in media controls.

Example: Accessible Audio Player

<audio controls>

    <source
        src="audio/background.mp3"
        type="audio/mpeg"
    >

</audio>

This example allows users to control audio playback instead of forcing the sound to begin automatically.

Example: Carousel Controls

<div
    class="carousel"
    aria-label="Featured books"
>

    <button type="button" id="previousSlide">
        Previous
    </button>

    <button type="button" id="pauseSlides">
        Pause slideshow
    </button>

    <button type="button" id="nextSlide">
        Next
    </button>

</div>

These buttons illustrate the controls a carousel should offer. JavaScript is needed to implement their behavior, including pausing automatic movement.

Recommended Practices

  • Avoid unnecessary automatic playback.
  • Provide visible controls for moving content.
  • Allow users to pause or stop animations.
  • Allow users to control audio playback.
  • Make carousel controls keyboard accessible.
  • Ensure that controls have descriptive labels.

Final Reminder

Accessible design gives users greater control over their browsing experience.

By providing clear controls, readable content, consistent navigation, and accessible alternatives, developers can create more inclusive websites.
