Computer Hardware and Software Fundamentals

Computer hardware refers to the tangible electronic components of a computer system, while computer software consists of the instructions and programs that control hardware operations.

This lesson explores computer architectures, processors, memory, storage, operating systems, programming languages, virtualization, software development, security, and emerging technologies.

1.2 Hardware-Software Interface

The Instruction Set Architecture (ISA) defines the instructions, registers, and behavior visible to software. Hardware implements these instructions through its internal microarchitecture.

Section 2: Von Neumann and Harvard Architectures

2.1 Von Neumann Architecture

The Von Neumann Architecture uses shared memory to store program instructions and data. The CPU communicates with memory through a shared bus system. 

         +----------------+
         |      CPU       |
         | ALU / CU / Reg |
         +--------+-------+
                  |
              Shared Bus
                  |
         +--------+-------+
         |  Main Memory   |
         | Instructions   |
         | and Data       |
         +----------------+

The Von Neumann bottleneck occurs when instruction fetching and data transfers compete for the same communication pathway.

2.2 Harvard Architecture

Harvard Architecture separates instruction memory and data memory, allowing independent access paths. 

Instruction Memory       Data Memory
         |                    |
         v                    v
  Instruction Bus         Data Bus
         |                    |
         +---------+----------+
                   |
                  CPU

Modern processors commonly use a modified Harvard architecture with separate L1 instruction and data caches.

Section 3: Central Processing Unit (CPU) Core Architecture

3.1 Core Structural Components

Component Function
Arithmetic Logic Unit (ALU) Performs mathematical and logical operations such as addition, subtraction, AND, OR, and XOR.
Control Unit (CU) Fetches and decodes instructions and sends control signals.
Registers Provide very fast internal storage for operands, addresses, and processor status.

3.2 Fetch-Decode-Execute Cycle

  1. Fetch: Retrieve an instruction from memory using the Program Counter.
  2. Decode: Interpret the opcode and identify the required operands.
  3. Execute: Perform the operation and store the result.

Section 4: Instruction Set Architectures — CISC vs. RISC

Instruction Set Architectures define the machine instructions supported by a processor.

Feature CISC RISC
Meaning Complex Instruction Set Computer Reduced Instruction Set Computer
Instruction Design Rich instructions, often variable-length Simpler, often fixed-length instructions
Memory Access Can support memory operands in complex instructions Typically uses load/store instructions
Examples x86-64 ARM, RISC-V, MIPS

Modern processor performance depends on implementation details as well as the ISA.

Section 5: Processor Pipelining and Superscalar Execution

5.1 Instruction Pipelining

Pipelining overlaps the execution stages of multiple instructions to increase throughput. 

FETCH → DECODE → EXECUTE → MEMORY → WRITE-BACK
  IF      ID       EX        MEM         WB

5.2 Pipeline Hazards

  • Structural Hazards: Multiple instructions require the same hardware resource.
  • Data Hazards: An instruction depends on the unfinished result of another.
  • Control Hazards: Branch instructions change the expected execution path.

Branch prediction and speculative execution help processors reduce control-hazard delays. Superscalar processors may issue multiple instructions during a clock cycle.

Section 6: Multi-Core and Parallel Processing Units

6.1 Multi-Core Processing

Multi-core processors integrate multiple CPU cores onto a single chip, allowing different tasks or threads to execute concurrently.

Symmetric Multiprocessing (SMP) allows multiple processors to share memory under one operating system.

Simultaneous Multithreading (SMT) allows a physical core to maintain and execute instructions from multiple hardware threads.

6.2 CPU vs. GPU

CPU GPU
Optimized for general-purpose, low-latency processing Optimized for high-throughput parallel workloads
Uses relatively complex processing cores Uses many parallel execution units
Runs operating systems and application logic Accelerates graphics, matrix, and tensor operations

7.2 ROM and Non-Volatile Memory

  • PROM: Programmable Read-Only Memory.
  • EPROM: Erasable Programmable ROM.
  • EEPROM: Electrically Erasable Programmable ROM.
  • Flash: Non-volatile semiconductor storage.

8.1 Memory Hierarchy

Memory systems balance access speed, capacity, and cost. Registers and caches are fast but limited in capacity, while secondary storage provides much larger persistent storage.

8.2 Cache Locality

  • Temporal Locality: Recently accessed data is likely to be accessed again.
  • Spatial Locality: Data near a recently accessed memory address may be accessed soon.

Section 9: Secondary and Tertiary Storage Technologies

9.1 HDD vs. SSD

HDD SSD
Stores data on magnetic spinning platters Stores data in NAND flash memory
Uses mechanical read/write heads Has no moving read/write mechanism
Experiences mechanical seek latency Generally provides faster random access
Often offers lower cost per GB Uses wear leveling to distribute flash writes

NVMe is a storage communication protocol commonly used with PCIe-connected SSDs.

Section 10: System Bus Topologies and Expansion Interfaces

10.1 System Buses

  • Data Bus: Transfers data between components.
  • Address Bus: Identifies memory or device locations.
  • Control Bus: Carries timing and control signals.

10.2 PCI Express (PCIe)

PCIe is a high-speed point-to-point serial expansion interface used for graphics cards, NVMe SSDs, and network adapters.

Common PCIe lane configurations include x1, x4, x8, and x16. PCIe 5.0 supports 32 GT/s per lane.

USB and Thunderbolt are additional interfaces for connecting peripherals and transferring data.

Section 11: Input/Output Architecture and Controllers

11.1 Memory-Mapped vs. Port-Mapped I/O

Memory-Mapped I/O maps device registers into the system memory address space.

Port-Mapped I/O uses a separate address space for peripheral communication, including x86 IN and OUT instructions.

11.2 Direct Memory Access

Direct Memory Access (DMA) enables controllers to transfer data between devices and memory without the CPU handling each individual byte.

Hardware interrupts notify the processor when a device or controller requires attention.

Section 12: Motherboards and Chipset Architectures

12.1 Motherboard Chipset Evolution

The motherboard connects the CPU, RAM, storage, expansion cards, and peripheral interfaces.

Older motherboard designs divided responsibilities between two chipset components:

  • Northbridge: Managed high-speed connections such as CPU, RAM, and graphics.
  • Southbridge: Managed lower-speed peripheral interfaces such as storage, USB, and audio.

Many modern processors integrate memory controllers and high-speed interfaces directly into the CPU, while a Platform Controller Hub (PCH) handles additional peripheral functions.

Section 13: Firmware and Boot System Architectures

13.1 BIOS vs. UEFI

BIOS UEFI
Legacy firmware environment Modern extensible firmware interface
Commonly associated with MBR booting Commonly associated with GPT booting
Uses traditional boot initialization Supports modular pre-boot services
Limited legacy boot features Can support Secure Boot verification

13.2 Boot Initialization

Firmware initializes hardware and performs startup checks such as the Power-On Self-Test (POST) before transferring control to the bootloader and operating system.

Section 14: Software System Classification and Taxonomy

Software Category Purpose Examples
System Software Manages hardware and system resources Windows, Linux, device drivers
Programming Utilities Supports code translation and development GCC, Clang, GDB, build tools
Application Software Performs end-user tasks Browsers, word processors, ERP systems

Middleware provides supporting services between software components, while firmware provides low-level control for hardware.

Section 15: Operating System Fundamentals

15.1 Kernel Architecture

The operating system kernel manages processes, memory, hardware access, and system resources.

  • Monolithic Kernel: Core operating system services run within a unified kernel address space.
  • Microkernel: Keeps the kernel minimal and places more services in user space.
  • Hybrid Kernel: Combines design characteristics of monolithic and microkernel systems.

15.2 System Calls

System calls allow applications to request operating system services such as file access, process creation, and memory allocation.

Section 16: Memory Management and Virtual Memory

16.1 Virtual Memory Mechanics

Virtual memory gives processes their own virtual address spaces, which are mapped to physical memory through page tables.

  • Paging: Divides memory into fixed-size pages and frames.
  • Page Table: Stores virtual-to-physical address mappings.
  • TLB: Caches recently used address translations.
  • Page Fault: Occurs when a required page is not currently mapped as needed.

Journaling helps preserve file system consistency after unexpected interruptions.

Compilers translate source code into a lower-level representation, while interpreters execute program instructions through a language runtime.

Just-in-Time (JIT) compilation translates selected code into machine instructions during program execution.

Section 20: Device Drivers and Hardware Abstraction Layers

20.1 Hardware Abstraction Layer (HAL)

A Hardware Abstraction Layer provides a consistent software interface to underlying hardware, reducing the need for operating system code to depend on individual device designs.

20.2 Device Drivers

Device drivers translate operating system requests into device-specific operations.

  • Kernel-mode drivers operate with privileged access.
  • User-mode drivers operate with more restricted permissions.
  • Interrupt handlers respond to hardware events.

Section 21: Application Software Systems and Frameworks

21.1 Software Architecture Patterns

Modern applications use architectural patterns to organize code, manage complexity, and support maintenance.

  • Model-View-Controller (MVC): Separates data, presentation, and application control responsibilities.
  • Microservices: Divides an application into independently deployable services.
  • REST APIs: Support communication through HTTP resources.
  • gRPC: Provides a framework for remote procedure calls.

Section 22: Virtualization and Hypervisor Technology

22.1 Type 1 vs. Type 2 Hypervisors

Type 1 Hypervisor Type 2 Hypervisor
Runs directly on a virtualization host Runs on top of a host operating system
Common in enterprise server environments Common in desktop virtualization
Examples: VMware ESXi, Proxmox VE Examples: VirtualBox, VMware Workstation

Hardware-assisted virtualization technologies include Intel VT-x and AMD-V.

Section 23: Containerization and Microservices Software

23.1 Operating System-Level Virtualization

Containers package applications and their dependencies while sharing the host operating system kernel.

  • Namespaces: Isolate processes, networks, and filesystem views.
  • Control Groups (cgroups): Control resource consumption such as CPU and memory.
  • Docker: Provides tools for building and running containers.
  • Kubernetes: Orchestrates containerized workloads across systems.

Section 24: Embedded Systems and Real-Time Software

24.1 Real-Time Operating Systems

Embedded systems perform specialized functions within devices such as vehicles, appliances, industrial controllers, and medical equipment.

A Real-Time Operating System (RTOS) emphasizes predictable task scheduling and response times.

  • Hard Real-Time: Missing a required deadline is considered a system failure.
  • Soft Real-Time: Missing a deadline reduces performance or quality but is not necessarily catastrophic.

Microcontrollers commonly integrate a CPU, memory, and peripheral interfaces on one chip.

Section 26: System Performance Metrics and Benchmarking

26.1 Performance Measurements

  • MIPS: Millions of Instructions Per Second.
  • FLOPS: Floating-Point Operations Per Second.
  • Clock Frequency: Processor cycles per second.
  • Latency: Time required to complete an operation.
  • Bandwidth: Amount of data transferred per unit of time.

26.2 Amdahl's Law

Amdahl's Law estimates the maximum speedup achievable by accelerating part of a program. 

Speedup = 1 / [(1 - P) + (P / S)]

P = Fraction of program that can be accelerated
S = Speedup of that portion

Section 27: Hardware Fault Tolerance and Maintenance

27.1 RAID Storage Levels

RAID Level Function
RAID 0 Data striping for performance; no redundancy
RAID 1 Data mirroring for redundancy
RAID 5 Striping with distributed parity; tolerates one drive failure
RAID 6 Distributed dual parity; tolerates two drive failures
RAID 10 Combines mirroring and striping

27.2 Reliability Technologies

  • ECC memory for detecting and correcting certain errors.
  • S.M.A.R.T. monitoring for storage health indicators.
  • Redundant power supplies for improved availability.

RAID improves availability but does not replace independent data backups.

Section 28: Software Quality Assurance and Hardening

28.1 Code Quality Enforcement

Software quality assurance helps detect defects, improve reliability, and reduce security vulnerabilities.

  • SAST: Static Application Security Testing analyzes code without executing the application.
  • DAST: Dynamic Application Security Testing evaluates a running application.
  • Unit Testing: Tests individual software components.
  • Integration Testing: Verifies interactions between components.
  • Patch Management: Applies updates that fix defects and vulnerabilities.

Section 29: Emerging Hardware and Software Frontiers

29.1 Emerging Computing Technologies

  • AI Accelerators: Tensor Processing Units (TPUs) and Neural Processing Units (NPUs) accelerate AI workloads.
  • Quantum Processing Units (QPUs): Use qubits and quantum properties such as superposition and entanglement.
  • Neuromorphic Computing: Explores hardware architectures inspired by biological neural networks.
  • Heterogeneous Systems: Combine CPUs, GPUs, and specialized accelerators in one computing environment.
