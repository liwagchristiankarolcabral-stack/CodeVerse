Operating System Fundamentals

An Operating System (OS) is foundational system software that manages computer hardware resources, provides services to application programs, and controls execution privileges in multi-user and multitasking environments.

The operating system acts as an intermediary between application software and computer hardware. It manages processes, memory, file systems, storage devices, input/output operations, and security.

Operating System Structure

+------------------------------------+
|          USER APPLICATIONS         |
|   Browsers, Games, Editors, IDEs   |
+------------------------------------+
|       OPERATING SYSTEM API         |
|     System Calls, Shell, GUI       |
+------------------------------------+
|          OPERATING SYSTEM          |
| Process, Memory, Files, I/O, etc.  |
+------------------------------------+
|          COMPUTER HARDWARE         |
|    CPU, RAM, Storage, Devices      |
+------------------------------------+

Core Objectives

  • Manage hardware resources efficiently.
  • Provide a convenient environment for applications.
  • Support multiple programs and users.
  • Enforce system protection and security.
  • Coordinate hardware and software operations.

1. Operating System Architecture and Kernel Structures

Operating systems use different kernel architectures to organize essential services such as process management, memory allocation, device drivers, and file systems.

Monolithic Kernel

A monolithic kernel places core operating system services inside one privileged kernel address space. This design provides fast communication between services but a faulty kernel component can affect the entire system.

Microkernel

A microkernel keeps only essential functions, including low-level memory management, interprocess communication, and scheduling, inside the kernel.

Other services such as device drivers and file systems can run in user space, improving modularity and fault isolation.

Hybrid Kernel

A hybrid kernel combines elements of monolithic and microkernel architectures to balance performance and modularity.

Exokernel

An exokernel exposes hardware resources more directly to application-level library operating systems, enabling specialized resource management.

Kernel Type Advantage Limitation
Monolithic Fast internal service communication Limited fault isolation
Microkernel Modularity and isolation IPC overhead
Hybrid Performance and flexibility Architectural complexity
Exokernel Application-specific optimization Complex application development

2. Hardware Abstraction and Execution Modes

Computer hardware uses privilege levels to prevent applications from directly accessing protected system resources.

User Mode

User mode is the restricted execution environment used by ordinary applications. Programs cannot directly execute privileged instructions or access protected kernel memory.

Kernel Mode

Kernel mode allows the operating system to perform privileged operations, configure hardware controllers, and manage protected memory.

Protection Rings

  • Ring 0: Kernel-level privilege.
  • Ring 3: User-level privilege.

Traps and Privilege Transitions

A system call can trigger a controlled transition from user mode to kernel mode through a CPU trap or dedicated system-call instruction.

A system call is the interface through which applications request operating system services.

Applications commonly use API libraries such as POSIX and Win32 to access system functionality.

  2. A library wrapper prepares the request.
  3. A system-call instruction enters kernel mode.
  4. The kernel identifies and executes the service.
  5. The result is returned to the application.

4. Process Management: Concepts and Abstraction

What Is a Process?

A process is a program currently in execution. Unlike a program stored on disk, a process has an active execution context, memory, and CPU state.

Process Memory Layout

Memory Region Purpose
Text Executable instructions
Data Initialized global and static variables
BSS Uninitialized global and static variables
Heap Dynamic memory allocation
Stack Function calls and local variables

Process Control Block (PCB)

The PCB stores information needed by the operating system to manage a process.

  • Process ID (PID)
  • Current process state
  • Program counter
  • CPU registers
  • Memory management information
  • Open files and I/O information

5. Process Scheduling and Lifecycle

Process scheduling determines when processes receive CPU time and how they move through their execution states.

Process States

  • New: Process is being created.
  • Ready: Waiting for CPU allocation.
  • Running: Currently executing.
  • Waiting: Waiting for an event or I/O operation.
  • Terminated: Execution has finished.
NEW --> READY --> RUNNING --> TERMINATED
          ^          |
          |          v
          +------- WAITING
             I/O Complete

Context Switching

A context switch occurs when the operating system saves the execution state of one process and restores the state of another.

Types of Schedulers

  • Long-Term: Controls admission of jobs.
  • Medium-Term: Manages suspension and swapping.
  • Short-Term: Selects the next ready process.

7. Threads and Concurrency Foundations

A thread is a basic unit of CPU execution within a process. Multiple threads in the same process share memory and resources while maintaining separate execution contexts.

Thread Components

  • Thread identifier
  • Program counter
  • Register set
  • Execution stack

Multithreading Models

Model Description
Many-to-One Many user threads map to one kernel thread.
One-to-One Each user thread maps to a kernel thread.
Many-to-Many User threads are multiplexed over kernel threads.

8. Process Synchronization and Race Conditions

When multiple threads access shared data concurrently, the final result may depend on the order of execution.

Race Condition

A race condition occurs when concurrent operations access shared resources without adequate synchronization.

Critical Section

A critical section is the portion of code that accesses shared resources and must be protected from conflicting execution.

Requirements for Correct Synchronization

  1. Mutual Exclusion: Only one process enters the protected section at a time.
  2. Progress: Eligible waiting processes can make progress.
  3. Bounded Waiting: A waiting process cannot be postponed indefinitely.

9. Synchronization Primitives

Mutex Locks

A mutex provides exclusive access to a shared resource using lock and unlock operations.

Semaphores

A semaphore is a synchronization primitive controlled by atomic wait and signal operations.

  • Binary Semaphore: Represents two logical states.
  • Counting Semaphore: Manages multiple resource instances.

Semaphore Example

wait(S):
    S.value = S.value - 1

    if S.value < 0:
        block current process


signal(S):
    S.value = S.value + 1

    if S.value <= 0:
        wake a waiting process

The wait and signal operations must execute atomically to preserve synchronization.

10. Deadlocks: Characterization and Handling

A deadlock occurs when two or more processes remain blocked indefinitely because each is waiting for a resource held by another.

The Four Coffman Conditions

  1. Mutual Exclusion: A resource cannot be shared simultaneously.
  2. Hold and Wait: A process holds resources while requesting others.
  3. No Preemption: Resources cannot be forcibly taken away.
  4. Circular Wait: Processes form a circular chain of resource dependencies.

Deadlock Example

Process P1:
Holds Resource A
Waiting for Resource B

Process P2:
Holds Resource B
Waiting for Resource A

P1 --> B --> P2 --> A --> P1

Result: DEADLOCK

11. Deadlock Prevention, Avoidance, and Recovery

Deadlock Prevention

Deadlock prevention ensures that at least one necessary deadlock condition cannot occur.

Deadlock Avoidance

Deadlock avoidance evaluates resource requests to ensure the system remains in a safe state.

Banker's Algorithm

The Banker's Algorithm checks whether resource allocation can allow all processes to complete in some safe execution sequence.

Structure Purpose
Available Currently available resources
Max Maximum process resource demands
Allocation Currently allocated resources
Need Remaining resources required 
Need = Max - Allocation

Deadlock Recovery

Recovery may involve terminating processes or reclaiming resources after detecting a deadlock.

12. Memory Management: Contiguous Allocation

Memory management controls the allocation, translation, and protection of memory used by executing processes.

Logical and Physical Addresses

  • Logical Address: Address generated by the CPU.
  • Physical Address: Actual location in RAM.

The Memory Management Unit (MMU) translates logical addresses into physical addresses.

Memory Fragmentation

Type Description
Internal Fragmentation Unused space inside allocated blocks.
External Fragmentation Free memory scattered into separate holes.

13. Non-Contiguous Memory: Paging Systems

Paging divides logical memory into fixed-size pages and physical memory into equally sized frames.

A page table maps logical page numbers to physical frame numbers.

Translation Lookaside Buffer

The TLB is a small hardware cache containing recently used page-to-frame translations.

It reduces the number of memory accesses required for address translation.

14. Advanced Paging Architectures

Multi-Level Paging

Multi-level paging divides page tables into smaller hierarchical structures to reduce memory overhead.

Hashed Page Tables

Hashed page tables use hash functions to locate page mappings efficiently in large address spaces.

Inverted Page Tables

An inverted page table stores an entry for each physical memory frame rather than a separate entry for every virtual page.

Method Key Idea
Multi-Level Hierarchical page tables
Hashed Hash-based address lookup
Inverted One entry per physical frame

15. Memory Segmentation

Segmentation divides a program's logical memory into variable-length segments.

Examples of Segments

  • Main program
  • Subroutines
  • Stack
  • Global data
  • Symbol table

Segment Address Translation

Logical Address:
(Segment Number, Offset)

Segment Table:
Segment Number --> Base + Limit

Physical Address:
Base + Offset

The MMU checks whether an offset is within the permitted segment boundary before performing memory access.

16. Virtual Memory Foundations

Virtual memory allows processes to use logical address spaces larger than available physical RAM.

Demand Paging

Demand paging loads a memory page into RAM only when that page is needed.

Page Fault Handling

  1. The CPU references a virtual address.
  2. The MMU detects that the required page is absent.
  3. A page fault trap transfers control to the kernel.
  4. The OS locates the missing page in secondary storage.
  5. The page is loaded into a physical frame.
  6. The page table is updated and execution resumes.

Thrashing

Thrashing occurs when excessive paging activity consumes system resources and significantly reduces useful processing time.

17. Page Replacement Algorithms

When no free physical memory frame is available, the operating system selects a page to replace.

Algorithm Replacement Rule
FIFO Replace the oldest loaded page.
Optimal Replace the page used farthest in the future.
LRU Replace the least recently used page.
Clock Use reference bits to grant second chances.

Belady's Anomaly

Under FIFO replacement, increasing the number of allocated memory frames can sometimes increase the number of page faults.

18. Storage and File System Abstraction

A file system organizes persistent data into files and directories.

Common File Attributes

  • File name and type
  • File size
  • Storage location
  • Access permissions
  • Creation and modification timestamps

Directory Structures

  • Single-Level: All files share one directory.
  • Two-Level: Each user has a separate directory.
  • Tree-Structured: Hierarchical folders.
  • Acyclic Graph: Supports shared files or directories.

19. File Allocation Methods

File allocation determines how file data blocks are stored on a disk.

Method Description
Contiguous Stores file blocks consecutively.
Linked Connects file blocks through pointers.
Indexed Uses an index containing block addresses.

Indexed Allocation

UNIX-like file systems commonly use inode-based structures to manage file metadata and block references.

20. Free Space Management

A file system tracks available storage blocks so new files can be allocated efficiently.

Free Space Tracking Methods

  • Bit Vector: One bit represents each disk block.
  • Linked List: Free blocks are connected through pointers.
  • Grouping: Free block addresses are stored in groups.
  • Counting: Tracks runs of consecutive free blocks.

21. Disk Infrastructure and Scheduling

Hard Disk Geometry

Traditional hard disks contain rotating platters divided into tracks and sectors.

  • Seek Time: Time to move the head to a track.
  • Rotational Latency: Time waiting for the target sector.

Disk Scheduling Algorithms

Algorithm Operation
FCFS Serves requests in arrival order.
SSTF Chooses the closest pending request.
SCAN Moves back and forth across tracks.
C-SCAN Services requests in one sweep direction.

22. Input/Output Subsystem Architecture

The I/O subsystem manages communication between the processor, memory, and peripheral devices.

Polling

The CPU repeatedly checks device status until an operation completes.

Interrupt-Driven I/O

A device sends an interrupt request when it needs processor attention.

Memory-Mapped I/O

Device registers are mapped into the processor's address space and accessed using memory instructions.

23. I/O Buffering, Caching, and Spooling

Buffering

Buffering temporarily stores data during transfers between devices operating at different speeds.

Caching

Caching keeps recently accessed data in faster memory to improve access speed.

Spooling

Spooling queues operations for devices that cannot process multiple requests simultaneously.

24. Protection and Access Control

Operating systems enforce access restrictions to protect files, devices, memory, and other resources.

Access Matrix

An access matrix describes which users or processes can perform operations on particular objects.

User File A File B
User 1 Read / Write Read
User 2 Read No Access

Access Control Lists

ACLs associate permission entries with individual protected objects.

Capability Lists

Capability lists associate access rights with a user or process domain.

25. System Security and Threat Mitigation

Operating system security protects system resources from unauthorized access, malicious software, and other security threats.

Authentication

Authentication verifies the identity of a user or system entity.

Authorization

Authorization determines what an authenticated entity is permitted to do.

Principle of Least Privilege

Users and processes should receive only the permissions necessary to perform their assigned tasks.

Access Control Models

  • Discretionary Access Control (DAC)
  • Role-Based Access Control (RBAC)

26. Virtualization and Hypervisors

Virtualization allows multiple isolated virtual machines to share the hardware of one computer.

Hypervisors

Type Description
Type 1 Runs directly on physical hardware.
Type 2 Runs as software on a host operating system.

Examples

  • VMware ESXi
  • Xen
  • VirtualBox
  • VMware Workstation

Containers

Containers isolate application environments while sharing the host operating system kernel.

27. Distributed and Multiprocessor Operating Systems

Symmetric Multiprocessing (SMP)

SMP allows multiple processors or CPU cores to share memory and operate under one operating system.

Non-Uniform Memory Access (NUMA)

NUMA architectures have memory access times that depend on the location of memory relative to the processor.

Distributed File Systems

Distributed file systems allow data to be accessed across multiple network-connected computers.

28. Real-Time Operating Systems

A real-time operating system is designed to execute important tasks within predictable timing constraints.

Hard Real-Time Systems

Missing a critical deadline is considered a system failure.

Soft Real-Time Systems

Missing a deadline reduces service quality but does not necessarily cause complete failure.

Real-Time Scheduling

  • Rate-Monotonic: Fixed priorities based on task periods.
  • Earliest Deadline First: Prioritizes the nearest deadline.

29. Modern Operating System Frontiers and Mobile Kernels

Modern operating systems support mobile devices, cloud environments, hardware virtualization, and advanced security mechanisms.

Android Binder

Binder is an interprocess communication mechanism used in Android systems.

Apple Darwin

Darwin provides the core operating system foundation used by Apple's operating systems.

Extended Berkeley Packet Filter (eBPF)

eBPF enables verified programs to execute in the Linux kernel for networking, monitoring, and other supported tasks.

Conclusion

Operating systems coordinate processing, memory, storage, input/output, and security to provide stable environments for application software.
