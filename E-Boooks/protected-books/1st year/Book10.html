Emerging Technologies and Artificial Intelligence

Emerging technologies are innovative developments transforming how individuals, businesses, and computer systems operate. Artificial intelligence, advanced computing, big data, and connectivity are important components of modern technology.

1. Overview of AI and Emerging Technologies

Artificial Intelligence serves as the brain driving modern technological evolution. It enables computer systems to perform tasks associated with human intelligence.

Four Foundational Pillars

  • Artificial Intelligence: Enables reasoning, perception, and learning through machine learning and neural networks.
  • Data and Analytics: Supplies information used for predictions, automated decisions, and model training.
  • Connectivity: Technologies such as 5G, IoT, cloud computing, and edge computing connect devices and services.
  • Advanced Computing: Quantum computing and blockchain introduce new computational and data-management capabilities.

2. Key Application Domains

Healthcare and Biometrics

AI supports genomic analysis, biometric identification, predictive diagnostics, and personalized healthcare.

Autonomous Systems

Self-driving vehicles, drones, and automated factories combine computer vision, LIDAR, and real-time sensor processing.

Smart Cities and Sustainability

Connected sensors and AI systems help optimize energy grids, public transportation, and environmental management.

Finance and E-Commerce

AI enables fraud detection, algorithmic trading, and personalized recommendations.

Programs and Processes in Computer Systems

A program is a passive collection of instructions stored on secondary storage, while a process is an active instance of a program executing under operating system management.

Understanding programs and processes is essential for studying operating systems, CPU scheduling, memory management, concurrency, and computer security.

Section 1: Foundational Definitions

What Is a Program?

A computer program consists of instructions written in a programming language and stored as an executable file or other form of executable code.

What Is a Process?

A process is an executing instance of a program. The operating system assigns resources such as memory, a process identifier, and execution context.

Program vs. Process

Program Process
Passive instructions Active execution
Stored on disk Uses RAM and CPU resources
Exists until deleted Exists during execution
Can launch multiple instances Has its own execution state

Section 2: Program Compilation and Linking

Compiled programs pass through a toolchain that transforms source code into executable machine instructions.

Compilation Pipeline

  1. Preprocessing: Expands macros and includes header files.
  2. Compilation: Translates source code into lower-level instructions.
  3. Assembly: Converts assembly instructions into machine code.
  4. Linking: Combines object files and resolves external references.

Static and Dynamic Linking

Static linking incorporates library code into an executable, while dynamic linking allows executables to use shared libraries loaded during program execution.

Executable Formats

  • ELF — Common in Linux and Unix systems
  • PE — Used by Microsoft Windows
  • Mach-O — Used by macOS

Section 3: Process Memory Architecture

A process uses a virtual address space divided into functional memory regions.

Memory Segments

Segment Purpose
Text Executable machine instructions
Data Initialized global and static variables
BSS Uninitialized global and static variables
Heap Dynamic memory allocation
Stack Function calls, local variables, and return addresses

Stack Overflow

A stack overflow occurs when stack memory usage exceeds its available limits, often because of excessive recursion.

Section 4: Process Control Block

The Process Control Block (PCB) is a kernel data structure containing information needed to manage and resume a process.

PCB Components

  • Process Identifier (PID)
  • Current process state
  • Program counter
  • Saved CPU registers
  • CPU scheduling information
  • Memory management information
  • Accounting and timing information
  • Open files and I/O information

Section 5: Process Lifecycle

Processes transition between operating system states throughout their execution.

Five Main Process States

  1. New: Process creation is underway.
  2. Ready: Waiting for CPU assignment.
  3. Running: Instructions are executing on the CPU.
  4. Waiting: Waiting for I/O or another event.
  5. Terminated: Execution has completed or stopped.
NEW → READY → RUNNING → TERMINATED
         ↑       |
         |       ↓
         └── WAITING
         (event completed)

Section 6: CPU Scheduling Concepts

CPU scheduling determines which ready process receives processor time next.

Preemptive Scheduling

The operating system can interrupt a running process and assign the CPU to another process.

Non-Preemptive Scheduling

A process continues running until it finishes, blocks, or voluntarily yields.

Scheduling Metrics

  • CPU Utilization
  • Throughput
  • Turnaround Time
  • Waiting Time
  • Response Time

Section 7: CPU Scheduling Algorithms

First-Come, First-Served

FCFS executes processes according to arrival order. Long tasks may delay shorter tasks, creating the convoy effect.

Shortest Job First

SJF prioritizes processes with the shortest estimated CPU burst.

Shortest Remaining Time First

SRTF is the preemptive form of SJF.

Priority Scheduling

Processes execute according to assigned priority. Aging can reduce starvation of low-priority tasks.

Round-Robin

Each process receives a fixed time quantum before the scheduler switches to another ready process.

Section 8: Process Creation and Control

Unix-like operating systems provide system calls for creating, replacing, waiting for, and terminating processes.

Core System Calls

  • fork() — Creates a child process.
  • exec() — Replaces the current process image.
  • wait() — Waits for a child and collects its termination status.
  • exit() — Terminates a process.

Orphan and Zombie Processes

An orphan is a child process whose parent has terminated. A zombie is a terminated process whose exit status has not yet been collected by its parent.

Section 9: Threads and Multithreading

A thread is a sequence of execution within a process. Multiple threads can share process resources while maintaining independent execution contexts.

Shared Resources

  • Code and data segments
  • Heap memory
  • Open files and sockets

Thread-Specific Resources

  • Stack
  • CPU registers
  • Execution state

Multithreading Models

  • Many-to-One
  • One-to-One
  • Many-to-Many

Section 10: Inter-Process Communication

Inter-Process Communication (IPC) allows separate processes to exchange information and coordinate activities.

IPC Mechanisms

  • Shared Memory: Processes access a designated common memory region.
  • Message Passing: Processes exchange messages through managed channels.
  • Pipes: Transfer data through byte streams.
  • Named Pipes: Enable communication through filesystem-visible channels.
  • Sockets: Support local or network communication.

Section 11: Process Synchronization

Synchronization coordinates access to shared resources and helps prevent race conditions.

Critical Section Requirements

  1. Mutual Exclusion
  2. Progress
  3. Bounded Waiting

Synchronization Tools

  • Mutex: Allows one thread to hold a lock at a time.
  • Semaphore: Coordinates access using a counter.
  • Spinlock: Repeatedly checks until a lock becomes available.

Section 12: Deadlocks and Starvation

A deadlock occurs when processes become permanently blocked because each waits for resources held by others.

Four Coffman Conditions

  1. Mutual Exclusion
  2. Hold and Wait
  3. No Preemption
  4. Circular Wait

Deadlock Handling

  • Prevention
  • Avoidance using Banker's Algorithm
  • Detection and Recovery
  • Ignoring rare deadlocks

Starvation occurs when a process waits indefinitely because other processes repeatedly receive resources first.

Section 13: Virtual Memory and Paging

Virtual memory gives each process an isolated address space while the Memory Management Unit translates virtual addresses into physical addresses.

Paging

Virtual memory is divided into pages, while physical RAM is divided into page frames.

Translation Lookaside Buffer

The TLB caches recent address translations to improve memory access performance.

Page Fault

A page fault occurs when a process accesses a page requiring operating system intervention, such as loading a page into RAM.

Section 14: Context Switching

Context switching saves the execution state of one process and restores the state of another process.

Context Switch Sequence

  1. An interrupt or scheduling event occurs.
  2. The operating system saves the current process state.
  3. The scheduler selects another process.
  4. The new process state is restored.
  5. Execution resumes.

Performance Overhead

  • Register saving and restoration
  • TLB effects
  • CPU cache misses

Section 15: System Security and Process Isolation

Hardware Protection Rings

Protection rings establish boundaries between privileged kernel operations and less-privileged user applications.

  • Ring 0 — Kernel privileges
  • Ring 3 — User application privileges

Address Space Layout Randomization

ASLR randomizes memory locations to make certain memory exploitation techniques more difficult.

Access Controls

User IDs and access control lists restrict operations according to assigned permissions.

Section 16: Asynchronous Execution and Signals

Signals notify processes about operating system events, exceptions, and termination requests.

Common POSIX Signals

  • SIGINT — Interrupt request.
  • SIGKILL — Forced termination.
  • SIGSEGV — Invalid memory access.
  • SIGCHLD — Child process status notification.

Event Loops

Event loops coordinate asynchronous tasks and non-blocking I/O. Technologies such as Node.js use event-driven execution to manage concurrent operations efficiently.

Section 17: Containers and Process Isolation

Containers package applications with their dependencies while running as isolated processes that share the host operating system kernel.

Linux Namespaces

Namespaces isolate process views of resources such as process IDs, networks, and filesystem mounts.

Control Groups

Control groups, or cgroups, measure and restrict resource consumption such as CPU, memory, and I/O.

Container Platforms

  • Docker
  • LXC

Section 18: Performance Monitoring and Metrics

Process monitoring helps identify resource bottlenecks, excessive CPU usage, memory problems, and slow system operations.

Metric Tools
CPU Saturation top, htop, mpstat
Resident Set Size ps, valgrind
I/O Wait Time iostat, iotop
System Call Latency strace, eBPF, perf

Conclusion

Programs and processes form the foundation of operating system execution. CPU scheduling, virtual memory, synchronization, security isolation, and performance monitoring enable efficient multitasking.
