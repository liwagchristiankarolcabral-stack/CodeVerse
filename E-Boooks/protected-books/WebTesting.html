Website Testing, Hosting, Deployment, and Maintenance

Learn the essentials of website testing, hosting, deployment, and maintenance to ensure reliable, secure, and well-performing websites.

Publishing Your Website

After creating a website using HTML, CSS, and JavaScript, the next step is to publish it online so other people can access it.

Publishing a website means making its files available through a web server that users can reach over the internet.

A website usually contains HTML documents, CSS stylesheets, JavaScript files, images, and other resources that work together to display its content.

Why Publish a Website?

  • Make your website accessible to other users.
  • Share projects and educational content online.
  • Build a professional portfolio.
  • Provide information or services through the web.
  • Allow users to access your website from different locations.

Learning Objectives

  • Understand web hosting and domain names.
  • Identify different website publishing methods.
  • Understand FTP, SFTP, and Rsync.
  • Explore web-based development environments.
  • Learn how online publishing platforms work.
  • Understand the basic GitHub Pages publishing process.

What Are the Options?

There are several ways to publish a website. The appropriate method depends on the type of website, available resources, technical experience, and desired level of control.

Common Website Publishing Options

  • Getting web hosting and a domain name.
  • Using a web-based integrated development environment.
  • Using an online publishing platform.

Comparison of Publishing Methods

Method Description Typical Use
Web Hosting Stores website files on a server. Professional websites and applications.
Web-Based IDE Provides an online code editor and preview. Learning and demonstrations.
Online Publishing Tool Publishes website files through a hosting platform. Static websites and portfolios.

Some publishing platforms provide free services for small projects, while others require payment for additional features or resources.

Getting Hosting and a Domain Name

Website owners who want greater control over their website's appearance, content, and configuration often obtain web hosting and register a domain name.

What Is Web Hosting?

Web hosting is a service that provides storage and server resources for a website.

A hosting provider stores website files and makes them accessible to visitors through the internet.

Examples of Website Files

my-website/
│
├── index.html
├── about.html
├── contact.html
│
├── css/
│   └── style.css
│
├── js/
│   └── script.js
│
└── images/
    └── logo.png

These files can be uploaded to a hosting server so that visitors can view the website.

What Is a Domain Name?

A domain name is a human-readable address used to locate a website on the internet.

Example

https://www.example.com

Domain names are registered through domain registrars and usually require periodic renewal.

Connecting Hosting and a Domain

A domain name must point to the server where the website is hosted.

This connection is commonly configured using Domain Name System (DNS) records.

Common DNS Records

Record Purpose
A Maps a domain name to an IPv4 address.
CNAME Maps one domain name to another domain name.

Tips for Finding Hosting and Domains

  • Compare hosting features and costs.
  • Check whether your desired domain is available.
  • Review renewal fees.
  • Consider technical support and reliability.
  • Verify that the hosting service supports your website's requirements.

Some hosting services are designed for static websites, while others support server-side applications, databases, and additional features.

Publishing to Your Server

Once a hosting service is available, website files must be transferred from the developer's computer to the hosting server.

Hosting providers may support several deployment methods, including file transfer tools, synchronization tools, and Git-based deployment.

Common File Transfer Methods

  • FTP and SFTP clients
  • Rsync
  • Git repositories
  • Hosting provider deployment tools

General Publishing Process

  1. Prepare the website files.
  2. Choose a hosting service.
  3. Obtain the server connection details.
  4. Transfer or deploy the website files.
  5. Configure the website address.
  6. Open the website in a browser.
  7. Test its pages and resources.

FTP and SFTP

File Transfer Protocol (FTP) is used to transfer files between computers over a network.

SSH File Transfer Protocol (SFTP) provides file transfer through a secure SSH connection.

Unlike traditional unencrypted FTP, SFTP protects file-transfer communications in transit.

Common File Transfer Clients

  • FileZilla
  • WinSCP
  • Cyberduck

Typical Connection Information

Protocol: SFTP

Host: sftp.example-host.com

Username: website-user

Port: 22

Remote Directory: /public_html/

These values are illustrative. Actual connection details and upload directories are supplied by the hosting provider.

Uploading Website Files

  1. Open an SFTP client.
  2. Enter the server connection details.
  3. Connect to the remote server.
  4. Locate the website's destination directory.
  5. Select the local website files.
  6. Upload them to the server.
  7. Verify that the files are accessible online.

Important Reminder

Use secure file transfer methods whenever possible and protect hosting credentials from unauthorized access.

Rsync

Rsync is a file synchronization tool that can copy and update files between local and remote computers.

It is commonly used through the command line and can transfer only the differences needed to synchronize files.

Basic Rsync Command

rsync -avz -e ssh ./website/ user@example.com:/var/www/html/

Command Explanation

Part Meaning
rsync Runs the synchronization program.
-a Uses archive mode.
-v Displays detailed progress information.
-z Compresses file data during transfer.
-e ssh Uses SSH as the remote connection method.

Advantages of Rsync

  • Supports efficient file synchronization.
  • Can preserve file attributes.
  • Supports remote transfers through SSH.
  • Can be integrated into deployment scripts.

Using a Web-Based IDE Such as CodePen

A web-based Integrated Development Environment (IDE) allows developers to write and test code directly inside a web browser.

Many web-based IDEs provide separate editors for HTML, CSS, and JavaScript, together with a live preview.

Examples

  • CodePen
  • JSFiddle
  • JSBin
  • Scrimba

How Web-Based IDEs Work

  1. Open the web-based development environment.
  2. Write HTML code in the HTML editor.
  3. Add styling in the CSS editor.
  4. Add interactive behavior using JavaScript.
  5. View the rendered webpage.
  6. Share the project through its available link.

Advantages

  • Easy to use for beginners.
  • Provides immediate visual feedback.
  • Useful for sharing code examples.
  • Often provides free basic features.

Limitations

  • May offer limited project configuration.
  • May restrict file storage.
  • May not support full backend applications.
  • May require paid plans for advanced features.

Using an Online Publishing Tool

Online publishing tools allow developers to make websites available on the internet without manually managing every server configuration.

GitHub

GitHub is a platform for hosting Git repositories, managing source code, and collaborating on projects.

Developers can upload their website files to a repository and use supported deployment features to publish them.

GitHub Pages

GitHub Pages is a static website hosting service that can publish HTML, CSS, JavaScript, and other static assets from a repository.

Netlify

Netlify provides website hosting and deployment features, including deployment from Git repositories.

It also offers features such as deployment previews, functions, and form handling.

Comparison

Platform Common Features
GitHub Pages Static hosting from a repository.
Netlify Static hosting, deployment automation, and additional services.

Both platforms provide options suitable for publishing static websites.

What Approach Would We Recommend?

For beginners publishing a static website, MDN recommends GitHub Pages because it provides a relatively straightforward publishing process.

Publishing with GitHub Pages

  1. Create a GitHub account.
  2. Create a repository for your website.
  3. Upload your HTML, CSS, JavaScript, and image files.
  4. Open the repository settings.
  5. Configure GitHub Pages deployment.
  6. Wait for the publishing process to complete.
  7. Open the generated website address.

Example Published Address

https://username.github.io/my-website/

The address depends on the GitHub username and repository name.

Important Limitation

GitHub Pages serves static content. It does not directly run persistent Node.js servers or SQLite databases.

Applications that require server-side login, sessions, and database operations need a hosting environment that supports those technologies.

What Are Browser Developer Tools?

Browser Developer Tools, commonly called DevTools, are built-in tools that help developers inspect, test, and debug websites.

Modern browsers such as Chrome, Firefox, Edge, and Safari include developer tools.

What Can Developer Tools Do?

  • Inspect HTML elements.
  • View and modify CSS styles.
  • Debug JavaScript code.
  • Display JavaScript errors.
  • Inspect network requests.
  • Test different viewport sizes.
  • Inspect page accessibility information.

Why Are Developer Tools Important?

Developer tools help identify problems that may not be obvious when viewing a webpage normally.

They allow developers to examine how the browser interprets and displays website code.

What Are DevTools?

DevTools display the current state of a webpage as it exists inside the browser.

The browser's current Document Object Model (DOM) may differ from the original HTML source because JavaScript can modify webpage elements dynamically.

Example

<p id="message">Hello</p>

<script>
    document.getElementById("message")
        .textContent = "Welcome!";
</script>

After the JavaScript executes, the displayed paragraph changes from "Hello" to "Welcome!".

Developer tools can inspect the updated DOM rather than only the original HTML source.

Common DevTools Panels

  • Elements or Inspector
  • Styles or CSS Editor
  • Sources or Debugger
  • Console
  • Network

How to Open the DevTools in Your Browser

Browser developer tools can usually be opened using keyboard shortcuts, browser menus, or the context menu.

Keyboard Shortcuts

Operating System Shortcut
Windows / Linux F12 or Ctrl + Shift + I
macOS Command + Option + I

Using the Context Menu

  1. Open a webpage.
  2. Right-click an element.
  3. Select Inspect or Inspect Element.
  4. Examine the selected element in DevTools.

Using Browser Menus

Chrome, Edge, Firefox, Opera, and Safari provide menu options for opening developer tools.

Safari may require enabling developer features in its advanced settings first.

The Inspector: DOM Explorer and CSS Editor

The Inspector allows developers to examine the HTML structure of a webpage and the CSS applied to its elements.

In Chrome and Edge, this functionality is commonly found in the Elements panel.

In Firefox, it is called the Inspector panel.

Common Inspector Features

  • View HTML elements.
  • Inspect element attributes.
  • Examine parent and child elements.
  • Modify HTML temporarily.
  • View applied CSS rules.
  • Inspect layout dimensions.

Exploring the DOM Inspector

The DOM Inspector displays the hierarchical structure of webpage elements.

Developers can select an element to inspect its attributes, content, and relationship to other elements.

Example HTML

<div class="card">

    <h2>Book Title</h2>

    <p>
        A short book description.
    </p>

</div>

Common Inspector Actions

  • Delete a selected node.
  • Edit an element's HTML.
  • Copy an element's markup.
  • Inspect element attributes.
  • Force hover, active, or focus states.

Important Reminder

Changes made directly through the DOM Inspector are generally temporary and do not automatically modify the original website files.

Exploring the CSS Editor

The CSS Editor displays the styling rules applied to a selected HTML element.

Developers can temporarily modify CSS properties and immediately observe the result.

Example CSS

.card {
    background-color: white;
    color: #202b40;
    padding: 20px;
    border-radius: 10px;
}

Testing CSS Changes

A developer can change the background color, padding, font size, or other properties using the Styles panel.

Computed Styles

The Computed panel shows the final calculated styles applied to an element.

Layout Information

The Layout panel can provide information about CSS Grid, Flexbox, and other layout systems.

CSS Box Model

The box model describes the content, padding, border, and margin of an element. 

Margin
  Border
    Padding
      Content

Useful CSS Debugging Tasks

  • Identify overridden CSS properties.
  • Inspect element spacing.
  • Test different colors.
  • Check font styles.
  • Investigate unexpected layouts.

The JavaScript Debugger

The JavaScript Debugger helps developers examine JavaScript execution and locate errors.

Developers can pause JavaScript execution at selected locations and inspect variables.

Common Debugger Features

  • Set breakpoints.
  • Pause script execution.
  • Inspect variable values.
  • Step through code.
  • View the call stack.
  • Examine variable scope.

Example JavaScript

let score = 0;

function addScore() {
    score += 10;
    console.log(score);
}

addScore();

A breakpoint can be placed inside the addScore function to inspect the value of the score variable.

Exploring the Debugger

The JavaScript Debugger commonly contains panels for source files, code inspection, and debugging information.

File List

The file list displays JavaScript files associated with the current webpage.

Source Code

The source code panel displays the selected JavaScript file.

Developers can place breakpoints on specific lines to pause execution.

Watch Expressions

Watch expressions allow developers to monitor selected expressions while debugging.

Breakpoints

A breakpoint is a designated location where JavaScript execution pauses.

Call Stack

The call stack displays the sequence of function calls leading to the current execution point.

Scopes

The Scopes panel displays variables accessible from the current execution context.

The JavaScript Console

The JavaScript Console allows developers to execute JavaScript commands and inspect errors directly in the browser.

Example: Display a Message

console.log("Hello, CodeVerse!");

Example: Display an Alert

alert("Welcome to CodeVerse!");

Example: Modify Page Styling

document.body.style.backgroundColor =
    "lightblue";

Example: JavaScript Error

console.log(unknownVariable);

If unknownVariable has not been declared, the browser reports a ReferenceError.

Common Console Uses

  • Test JavaScript expressions.
  • Display debugging messages.
  • Inspect objects and variables.
  • Identify runtime errors.
  • Experiment with DOM manipulation.

The Network Inspector

The Network Inspector displays the network requests and responses generated while loading and using a webpage.

It helps developers determine whether website resources are loading correctly.

Resources Commonly Requested

  • HTML documents
  • CSS stylesheets
  • JavaScript files
  • Images
  • Fonts
  • API responses

Example Network Requests

Resource Status
index.html 200 OK
style.css 200 OK
script.js 200 OK
missing-image.png 404 Not Found

How to Use the Network Inspector

  1. Open Developer Tools.
  2. Select the Network panel.
  3. Reload the webpage.
  4. Examine the requests displayed.
  5. Check response status codes.
  6. Investigate failed requests.

HTTP Statuses

HTTP status codes are three-digit numbers returned by servers to describe the result of a request.

These codes help developers determine whether a request succeeded, redirected, failed because of a client issue, or encountered a server problem.

Common HTTP Status Codes

Status Code Meaning Description
200 OK The requested resource was successfully delivered.
301 Moved Permanently The resource has permanently moved to another location.
304 Not Modified The cached resource can be reused because it has not changed.
403 Forbidden The server refuses access to the requested resource.
404 Not Found The requested resource could not be found.
500 Internal Server Error The server encountered an unexpected problem.
503 Service Unavailable The service is temporarily unable to handle the request.

HTTP Status Code Categories

  • 1xx: Informational responses.
  • 2xx: Successful requests.
  • 3xx: Redirection responses.
  • 4xx: Client error responses.
  • 5xx: Server error responses.

Example: Missing File

GET /images/logo.png

HTTP/1.1 404 Not Found

A 404 response may indicate that the file does not exist at the requested path, the filename is incorrect, or the file was not uploaded.

Example: Successful Request

GET /index.html

HTTP/1.1 200 OK

A 200 response indicates that the request was successful.

Example: Cached Resource

GET /css/style.css

HTTP/1.1 304 Not Modified

A 304 response allows the browser to reuse a previously cached representation when the relevant cache validation conditions are satisfied.

Why HTTP Status Codes Matter

  • Help identify missing resources.
  • Assist with debugging API requests.
  • Reveal server-side failures.
  • Explain redirects and caching behavior.
  • Help developers troubleshoot website problems.
