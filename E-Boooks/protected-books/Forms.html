Forms and Input Validation

Learn how to create interactive web forms and validate user inputs to ensure accurate and secure data submission.

Your first form

HTML forms are an important part of web development. They allow users to enter information and interact with websites and web applications.

Forms are commonly used for registration, login, contact messages, surveys, searches, and collecting other types of user information.

In this lesson, you will learn how to design a simple contact form, create its HTML structure, apply basic CSS styling, and understand how form data is sent to a web server.

Learning Objectives

  • Understand what web forms are and how they work.
  • Learn how to plan and design a simple form.
  • Understand the form, label, input, textarea, and button elements.
  • Apply basic CSS styling to form controls.
  • Understand how form data is submitted to a server.

Prerequisites

A basic understanding of HTML elements, attributes, and document structure is recommended.

What are web forms?

Web forms provide a way for users to enter information into a website or application. The information may be sent to a server for processing and storage or used directly within the webpage.

Forms contain interactive elements called form controls. These controls allow users to provide different types of information.

Common Form Controls

  • Text Fields: Allow users to enter a single line of text.
  • Text Areas: Allow users to enter multiple lines of text.
  • Dropdown Lists: Allow users to choose from predefined options.
  • Checkboxes: Allow users to select or deselect options.
  • Radio Buttons: Allow users to select one option from a group.
  • Buttons: Allow users to submit, reset, or interact with a form.

Form Validation

Form controls can include validation rules to help ensure that users provide information in the expected format.

For example, an email field can check whether the entered text resembles a valid email address. 

<input type="email" required>

The required attribute indicates that the field must be completed before the form can be submitted normally.

Form labels are also important because they help users understand the purpose of each control and improve accessibility.

Designing your form

Before writing the HTML code, it is important to plan what information the form should collect.

Creating a simple sketch or mockup can help developers decide which controls are needed and how the form should be organized.

Keep Forms Simple

A form that requests too much information can discourage users from completing it. Good form design focuses on collecting only the necessary information.

Example: Contact Form

In this lesson, we will create a simple contact form containing three fields and one submission button.

  • Name — identifies the person sending the message.
  • Email — provides an address for communication.
  • Message — contains the information the user wants to send.
  • Submit Button — sends the completed form data.

Implementing our form HTML

After planning the form, the next step is to create its structure using HTML.

The contact form will use five important HTML elements.

HTML Element Purpose
<form> Defines the form container.
<label> Describes a form control.
<input> Creates input fields and other controls.
<textarea> Creates a multiline text field.
<button> Creates an interactive button.

These elements work together to create a functional HTML form.

The <form> element

The <form> element defines a section of a webpage that contains interactive form controls.

It acts as the main container for collecting and submitting user information.

Basic Form Syntax

<form action="/my-handling-form-page" method="post">

    <!-- Form controls go here -->

</form>

Important Form Attributes

Attribute Description
action Specifies the URL where the form data will be sent.
method Specifies the HTTP method used to submit the form data.

The action Attribute

The action attribute identifies the destination that will receive the submitted form information. 

<form action="/contact" method="post">
    ...
</form>

In this example, the form sends its data to the /contact endpoint.

The method Attribute

The method attribute determines which HTTP method is used when submitting the form.

  • GET: Sends form values through the URL query string.
  • POST: Sends form values in the HTTP request body.

Contact forms commonly use POST because the submitted information is intended to be processed by the server.

The <label>, <input>, and <textarea> elements

A contact form needs controls for entering a name, email address, and message.

Each control should have an associated label that clearly describes the information the user is expected to enter.

Complete Input Fields Example

    <p>
        <label for="name">Name:</label>

        <input
            type="text"
            id="name"
            name="user_name"
        >
    </p>

    <p>
        <label for="mail">Email:</label>

        <input
            type="email"
            id="mail"
            name="user_email"
        >
    </p>

    <p>
        <label for="msg">Message:</label>

        <textarea
            id="msg"
            name="user_message"
        ></textarea>
    </p>

</form>

The <label> Element

The label element provides a text description for a form control. 

<label for="username">Username:</label>

<input
    type="text"
    id="username"
    name="username"
>

The label's for attribute should match the id of the corresponding form control.

Why Labels Are Important

  • They explain the purpose of form controls.
  • They improve accessibility for screen reader users.
  • Clicking a label can focus its associated input.
  • They make forms easier to understand and use.

The <input> Element

The <input> element creates different types of input controls.

Its type attribute determines how the control behaves.

Text Input

<input type="text" name="user_name">

The text input type creates a single-line field for entering text.

Email Input

<input type="email" name="user_email">

An email input provides built-in checks for email address formatting. On mobile devices, it can also display a keyboard suited to email entry.

The <textarea> Element

The <textarea> element creates a field for entering multiple lines of text. 

<textarea
    id="message"
    name="message"
></textarea>

Textareas are commonly used for comments, descriptions, feedback, and messages.

Input vs. Textarea

Input Textarea
Usually used for single-line text. Used for multiline text.
It is a void element. It requires a closing tag.
Its default value can use the value attribute. Its default value is placed between its tags.

Default Value for Input

<input
    type="text"
    value="John Doe"
>

Default Value for Textarea

<textarea>Enter your message here.</textarea>

The input element uses the value attribute, while the textarea element stores its initial text between the opening and closing tags.

The <button> element

The <button> element creates an interactive button.

In a contact form, a submit button allows users to send the information they have entered.

Submit Button Example

<p class="button">

    <button type="submit">
        Send your message
    </button>

</p>

Button Types

The button element supports three common values for its type attribute.

Button Type Purpose
submit Submits the form data.
reset Restores form controls to their initial values.
button Creates a button for custom functionality.

Submit Button

<button type="submit">
    Submit
</button>

A submit button triggers the form submission process.

Reset Button

<button type="reset">
    Reset
</button>

A reset button restores form fields to their default values. Reset buttons should be used carefully because users may accidentally erase information they have entered.

Regular Button

<button type="button">
    Click Me
</button>

A regular button does not submit or reset a form automatically. JavaScript can be used to define its behavior.

Button vs. Input Button

<input type="submit" value="Send">

<button type="submit">
    Send
</button>

Both examples create submit controls. However, the button element can contain HTML content, while the input element uses its value attribute for its label.

Basic form styling

HTML forms work without CSS, but their default appearance may not match the design of a website.

CSS allows developers to improve the spacing, alignment, borders, typography, and overall presentation of form controls.

Adding CSS to a Form

CSS can be written inside a style element in the document head or placed in an external stylesheet. 

<style>

    /* Form CSS goes here */

</style>

Styling the Form Container

.demo-contact-form {
    display: block;
    max-width: 450px;
    margin: 20px auto;
    padding: 20px;
    border: 1px solid #cccccc;
    border-radius: 12px;
}

The form has a maximum width, centered margins, internal spacing, a border, and rounded corners.

Styling Form Labels

.demo-contact-form label {
    display: inline-block;
    min-width: 90px;
    margin-bottom: 8px;
    font-weight: bold;
}

This provides consistent spacing and makes the labels easier to read.

Styling Input and Textarea

.demo-contact-form input,
.demo-contact-form textarea {
    width: 100%;
    padding: 10px;
    box-sizing: border-box;
    border: 1px solid #999999;
    border-radius: 6px;
    font: inherit;
}

Example Explained

  • width: 100% allows controls to fill the available container width.
  • padding creates space inside the controls.
  • box-sizing: border-box includes padding and borders within the declared width.
  • font: inherit makes the controls use the surrounding font settings.

Styling Focused Fields

.demo-contact-form input:focus,
.demo-contact-form textarea:focus {
    outline: 2px solid #3157a4;
    outline-offset: 2px;
}

The :focus pseudo-class applies styling when a control receives keyboard or pointer focus.

Styling the Textarea

.demo-contact-form textarea {
    min-height: 120px;
    resize: vertical;
}

The textarea is given additional height for longer messages. Vertical resizing allows users to expand the text area when needed.

Styling the Submit Button

.demo-contact-form button {
    background-color: #3157a4;
    color: white;
    border: none;
    padding: 12px 20px;
    border-radius: 6px;
    cursor: pointer;
}

.demo-contact-form button:hover {
    background-color: #24427f;
}

Why Form Styling Matters

  • Improves readability and visual consistency.
  • Makes form fields easier to recognize.
  • Provides clear visual feedback during interaction.
  • Helps organize information logically.
  • Supports a better overall user experience.

Sending form data to your web server

After a user completes a form, the collected information can be sent to a web server for processing.

The form element controls where the information is sent and which HTTP method is used.

The Importance of the name Attribute

Each form control that submits data should have a name attribute.

The browser uses this attribute to identify the information being sent to the server. 

<input
    type="text"
    name="user_name"
>

In this example, the entered information is associated with the name user_name.

Form Data as Name-Value Pairs

When a form is submitted, the browser sends the collected values using their corresponding control names.

Name Example Value
user_name Juan Dela Cruz
user_email juan@example.com
user_message Hello! I would like to ask a question.

Example Form Data

user_name=Juan Dela Cruz

user_email=juan@example.com

user_message=Hello! I would like to ask a question.

These values illustrate the information that a server could receive from the contact form.

How Form Submission Works

  1. The user enters information into the form.
  2. The user selects the submit button.
  3. The browser performs applicable form validation.
  4. The browser sends an HTTP request to the form action URL.
  5. The server receives the submitted name-value pairs.
  6. The server processes the data and returns a response.

Server-Side Processing

A server-side program is responsible for deciding what happens to the submitted information.

Depending on the application, the server might save the data to a database, send a notification, or perform another operation.

Server-side processing can be implemented using technologies such as Node.js, PHP, Python, Java, or C#.

Important Reminder

HTML alone does not store form submissions in a database. A working server endpoint is needed to receive and process the information.

Client-side validation can improve usability, but the server must also validate submitted data before trusting or storing it.

Final Reminder

Building a web form involves more than placing input fields on a page. A good form should be understandable, accessible, appropriately styled, and connected to a reliable submission process.

Understanding these fundamentals prepares you to build more advanced forms with validation, additional controls, and server-side functionality.

HTML input types

Choose appropriate input types for text, email, passwords, numbers, dates, URLs, and telephone numbers. Semantic input types provide browser features and better mobile keyboards.

Example

<label for="email">Email</label>
<input id="email" name="email" type="email" required>

Key takeaway

Use type="password" for masked entry, but remember masking is not encryption. Use type="tel" for phone numbers because phone number formats vary.

Checkboxes and radio buttons

Checkboxes allow independent selections; radio buttons with the same name represent one choice from a group. Every control needs an understandable label.

Example

<label><input type="checkbox" name="updates"> Send updates</label>
<fieldset>
  <legend>Preferred contact</legend>
  <label><input type="radio" name="contact" value="email"> Email</label>
  <label><input type="radio" name="contact" value="phone"> Phone</label>
</fieldset>

Key takeaway

Unchecked checkboxes are generally omitted from submitted form data. Set a value when the server needs to distinguish selections.

Dropdown lists with select and option

Use select when the user should choose from a list of predefined values. Option values are submitted to the server, while visible text explains the choices.

Example

<label for="course">Course</label>
<select id="course" name="course" required>
  <option value="">Choose a course</option>
  <option value="bsit">BS Information Technology</option>
  <option value="bscs">BS Computer Science</option>
</select>

Key takeaway

Avoid very long dropdowns when a search interface would be easier to use.

Grouping fields with fieldset and legend

Related form fields should be grouped with fieldset and described with legend. This is especially helpful for sets of radio buttons and checkboxes.

Example

<fieldset>
  <legend>Delivery preference</legend>
  <label><input type="radio" name="delivery" value="pickup"> Pickup</label>
  <label><input type="radio" name="delivery" value="courier"> Courier</label>
</fieldset>

Key takeaway

The legend should clearly explain the question answered by the grouped controls.

Placeholder, autocomplete, and inputmode

Placeholder text offers a temporary hint, not a substitute for a persistent label. Autocomplete helps browsers fill familiar data; inputmode suggests an appropriate virtual keyboard.

Example

<label for="phone">Phone number</label>
<input id="phone" name="phone" type="tel" autocomplete="tel" inputmode="tel" placeholder="e.g., 0912 345 6789">

Key takeaway

Use autocomplete values such as name, email, current-password, and new-password when appropriate.

Required fields and built-in validation

The required attribute prevents normal submission of an empty required control. Browser constraint validation can check input type and other declared rules before a form is submitted.

Example

<label for="fullName">Full name</label>
<input id="fullName" name="fullName" required>

Key takeaway

Mark required fields clearly. Browser validation is helpful but never replaces validation on the server.

Numeric and date constraints

The min, max, and step attributes specify allowed ranges and increments for supported controls. They are useful for quantities, dates, and other bounded values.

Example

<label for="quantity">Quantity (1–10)</label>
<input id="quantity" name="quantity" type="number" min="1" max="10" step="1" required>

Key takeaway

A server must independently enforce the same range because clients can bypass browser constraints.

Text length restrictions

The minlength and maxlength attributes describe length requirements for text inputs and textareas. Explain the requirements before users submit.

Example

<label for="username">Username (4–20 characters)</label>
<input id="username" name="username" minlength="4" maxlength="20" required>

Key takeaway

Character length rules do not determine whether a username is unique or safe; the server must perform those checks.

Pattern-based input validation

The pattern attribute applies a regular-expression rule to supported text-like input controls. Provide an example of the expected format to help users succeed.

Example

<label for="code">Code (three uppercase letters)</label>
<input id="code" name="code" pattern="[A-Z]{3}" title="Enter three uppercase letters" required>

Key takeaway

Avoid overly restrictive patterns for names, addresses, and phone numbers; real-world formats vary.

Valid and invalid CSS states

CSS pseudo-classes such as :valid, :invalid, :required, and :focus-visible can provide visual feedback. Use explanatory text as well as color.

Example

input:focus-visible { outline: 3px solid #3157a4; }
input:invalid:not(:placeholder-shown) { border-color: #b42318; }

Key takeaway

Be careful not to show error styling before a user has had an opportunity to enter data.

JavaScript Constraint Validation API

JavaScript can inspect a control’s validity, call checkValidity(), or display a browser validation message with reportValidity().

Example

const form = document.querySelector("#signupForm");
if (!form.checkValidity()) {
  form.reportValidity();
}

Key takeaway

The validity property provides flags such as valueMissing, typeMismatch, and patternMismatch.

Custom validation messages

Use setCustomValidity() to describe application-specific rules that built-in attributes cannot express. Clear custom errors when the value changes.

Example

const password = document.querySelector("#password");
password.addEventListener("input", () => {
  password.setCustomValidity(password.value.includes(" ")
    ? "Password cannot contain spaces." : "");
});

Key takeaway

Always ensure that custom messages are accurate and that users can correct the field.

Handling submit events in JavaScript

The submit event occurs when a form is submitted. Use preventDefault() when JavaScript will handle submission, then validate and send data intentionally.

Example

document.querySelector("#contactForm").addEventListener("submit", async (event) => {
  event.preventDefault();
  if (!event.currentTarget.reportValidity()) return;
  // Send validated values to your server.
});

Key takeaway

A click handler on a button is not a complete substitute for a form submit handler; keyboard submissions matter too.

Collecting values with FormData

The FormData API collects successful form controls by their name attributes. It can be used with fetch() to submit text fields and files.

Example

const form = document.querySelector("#contactForm");
const data = new FormData(form);
console.log(data.get("email"));

Key takeaway

Do not assume every expected value exists; unchecked controls may not appear in FormData.

Submitting forms with fetch

The Fetch API can submit form values asynchronously and handle server responses without navigating away from the current page.

Example

const form = document.querySelector("#contactForm");
const response = await fetch(form.action, {
  method: "POST",
  body: new FormData(form),
  credentials: "same-origin"
});
if (!response.ok) throw new Error("Submission failed");

Key takeaway

When sending FormData, do not manually set the multipart Content-Type header; the browser supplies the boundary.

File uploads and validation

File inputs let users select files. Accept hints can narrow file choices, but the server must verify file type, size, and safe storage.

Example

<label for="resume">Upload résumé (PDF)</label>
<input id="resume" name="resume" type="file" accept=".pdf,application/pdf">

Key takeaway

The accept attribute is only a browser hint. Never trust a file extension or client-provided MIME type alone.

Accessible error messages

Error messages should identify the affected field and explain how to fix it. Associate errors with controls using aria-describedby and announce important changes when needed.

Example

<label for="studentEmail">Email</label>
<input id="studentEmail" name="email" aria-describedby="emailHelp">
<small id="emailHelp">Enter a valid email address.</small>

Key takeaway

Avoid using only red borders or icons to communicate an error.

Server-side validation and security

All submitted data must be checked on the server, even when browser validation is present. Enforce required fields, length limits, permitted values, authorization, and business rules.

Example

app.post("/api/contact", (req, res) => {
  const email = String(req.body.email ?? "").trim();
  if (email.length > 254 || !email.includes("@")) {
    return res.status(400).json({ message: "Invalid email." });
  }
  res.json({ success: true });
});

Key takeaway

This abbreviated example is illustrative, not production-ready email validation. Use trusted validation libraries and parameterized database queries.

CSRF, XSS, and safe form processing

Secure form handling must consider cross-site request forgery, cross-site scripting, and injection attacks. Use framework protections, output encoding, CSRF defenses where needed, and parameterized queries.

Example

// Example: parameterized database query
await db.query(
  "INSERT INTO contacts (email) VALUES ($1)",
  [email]
);

Key takeaway

Client-side sanitization alone is not sufficient. Encode data for its output context and protect authenticated state-changing requests.

Testing forms and validation

Test valid submissions, missing fields, wrong formats, boundary values, keyboard navigation, and server errors. Verify that failures do not erase entered data unnecessarily.

Example

// Suggested test cases:
// 1. Empty required field
// 2. Invalid email
// 3. Minimum and maximum length
// 4. Keyboard-only submission
// 5. Server returns 400 or 500

Key takeaway

Test on mobile and desktop, with assistive technologies where possible, and confirm the server rejects bypassed client-side checks.
