Web Browsers, Servers, and HTTP/HTTPS

Web browsers are software used to access and view websites, servers are systems that store and deliver website data, and HTTP/HTTPS are protocols that allow browsers and servers to communicate, with HTTPS providing a secure connection.

How browsers load websites

What files are returned in HTTP responses?

To summarize the overview of web technologies we looked at in the last article, HTTP responses (to requests for a web page) will generally contain some of the following file types:

HTML files, which specify the web page content and its structure. CSS files, which specify styling and layout information. JavaScript files, which specify the behavior of interactive parts of the web page. Media assets such as images, videos, audio files, PDFs, and SVGs, which are embedded in web pages or otherwise displayed by the browser. Other kinds of file that the browser can't handle natively and therefore hands off to a relevant app on the device to render, for example Word or Pages documents, PowerPoint slide decks, and Open Office files. Web page rendering When the user navigates to a new web page (by clicking a link, or entering a web address in the browser address bar), several HTTP requests are sent, and several files are sent back in HTTP responses. The files received in these responses are processed by the browser and put together into a web page that the user can interact with. This process of assembling the pieces into a web page is called rendering.

The following sections provide a high-level explanation of how a browser renders a web page. Keep in mind that this is a simplified description, and that different browsers will handle the process in different ways. However, this will still give you an idea of how things work

Handling HTML

To start with, the HTML file that contains the web page content and defines its structure is received by the browser, and parsed. The browser converts it into a tree-like structure called a DOM tree (Document Object Model). The DOM represents the HTML document structure in the computer's memory. Take this basic HTML snippet as an example:

Each element, attribute, and piece of text in the HTML becomes a DOM node in the tree structure. The nodes are defined by their relationship to other DOM nodes. Some elements are parents of child nodes, and child nodes have siblings. The browser will parse this HTML and create the following DOM tree from it:

Certain HTML elements, when parsed, will trigger more HTTP requests:

  • <link> elements referencing external CSS stylesheets.
  • <script> elements referencing external JavaScript files.
  • Elements such as <img>, <video>, and <audio>, which reference media files you want to embed in the web page.

Parsing CSS and rendering the page

Next, the CSS is handled.

  • 1.The browser parses the CSS found on the page (either included in the HTML file, or fetched from external stylesheets), and sorts the different CSS styling rules into different "buckets" based on which HTML elements (represented in the DOM as items called nodes) they will be applied to. The browser then attaches styles to different elements as required (this intermediate step is called a render tree).
  • 2.The render tree is laid out in the structure it should appear in after the rules have been applied. This includes any images and other media files that are to be embedded in the page.
  • 3.The visual display of the page is shown on the screen (this stage is called painting).

The browser: a hostile and an awesome programming environment

Front-end web development can sometimes be frustrating, and some people consider the browser to be a hostile programming environment. This is because, unlike other programming environments, it is much harder to make guarantees about the environment your code will run on. You cannot know ahead of time all the different combinations of operating system, browser, language, location, network connection, CPU, GPU, memory, battery life, etc., that your users will have, therefore you cannot guarantee a perfect user experience for all of them.

Modern browsers tend to implement web standards pretty consistently, but there is still a lot of uncertainty to navigate. As a web developer, you will need to embrace that uncertainty, programming defensively and being conservative with the features you use. This relies on adhering to the best practices outlined in the previous article.

On the upside, the web is also an awesome programming environment, for many reasons.

  • For a start, it is designed with universal access in mind. The web's basic state is accessible and linkable. Some of these basics are harder to achieve in other environments.
  • App delivery across the web is simple and powerful. You don't need to take your users through a complicated installation process: you just point them to a web address and off they go.
  • App updates are usually straightforward. In many cases, visitors can see new versions of an application when they reload their browser tab. You don't need to worry about getting visitors to regularly download and install software updates.
  • The web community is vibrant and helpful. As we discuss later on in our Research and learning article, there are lots of places you can go to ask for help, and great resources available to learn from.

5. What Is a Web Browser?

Overview

A browser is a client application that requests web resources, interprets HTML, CSS, and JavaScript, and presents an interactive document.

How It Works

The address bar accepts a URL, while the browser engine handles navigation, rendering, and user input.

Important Concept

A browser is not the same as a search engine: the browser displays pages; a search engine helps find them.

Try It Yourself

Open the same page in two browsers and compare the layout and available developer tools.

Key Takeaway

A browser is a client application that requests web resources, interprets HTML, CSS, and JavaScript, and presents an interactive document.

6. Major Components of a Browser

Overview

Modern browsers contain a user interface, networking code, a rendering engine, JavaScript execution, storage, and security boundaries.

How It Works

The browser coordinates these components so a page can load while protecting other tabs and the operating system.

Important Concept

A rendering engine draws content; a JavaScript engine executes scripts. They have different responsibilities.

Try It Yourself

Use the browser task manager, where available, to inspect tab processes.

Key Takeaway

Modern browsers contain a user interface, networking code, a rendering engine, JavaScript execution, storage, and security boundaries.

7. The Client–Server Model

Overview

A client requests a service or resource and a server processes the request and sends a response.

How It Works

The browser usually acts as the client. An application server may query a database before responding.

Important Concept

The same server may serve static assets and dynamic API responses.

Try It Yourself

Draw the flow from a browser request to a server response.

Key Takeaway

A client requests a service or resource and a server processes the request and sends a response.

8. What Is a Web Server?

Overview

A web server is software, and often the computer running it, that receives HTTP requests and returns resources or application results.

How It Works

Servers may return HTML files, images, JSON, redirects, or error messages.

Important Concept

Examples of web server software include Nginx and Apache; Node.js applications can also handle HTTP requests.

Try It Yourself

Run a local development server and observe the address and port it listens on.

Key Takeaway

A web server is software, and often the computer running it, that receives HTTP requests and returns resources or application results.

9. Understanding URLs and Their Parts

Overview

A URL identifies where a resource can be accessed. It commonly includes a scheme, host, optional port, path, query, and fragment.

How It Works

For https://example.com:443/books?id=2#chapter, the scheme is https, the host is example.com, and the query is id=2.

Important Concept

A fragment is normally handled by the browser and is not sent in the HTTP request target.

Example

https://example.com:443/books?id=2#chapter

Try It Yourself

Identify the scheme, host, path, query, and fragment of a URL you use.

Key Takeaway

A URL identifies where a resource can be accessed. It commonly includes a scheme, host, optional port, path, query, and fragment.

10. Domain Names and DNS Resolution

Overview

The Domain Name System (DNS) helps translate hostnames into network information such as IP addresses.

How It Works

A browser or operating system may use cached DNS information before asking a resolver.

Important Concept

DNS answers do not themselves encrypt web traffic; HTTPS/TLS handles transport security.

Try It Yourself

Compare a hostname with the IP address returned by a DNS lookup.

Key Takeaway

The Domain Name System (DNS) helps translate hostnames into network information such as IP addresses.

11. IP Addresses and Port Numbers

Overview

IP addresses identify network endpoints, while port numbers help direct traffic to a particular service.

How It Works

Common default ports are 80 for HTTP and 443 for HTTPS. A local development server may use port 3000.

Important Concept

A port is not part of a webpage path; it identifies a network service on the host.

Try It Yourself

Visit a local service at http://localhost:3000 and identify its port.

Key Takeaway

IP addresses identify network endpoints, while port numbers help direct traffic to a particular service.

12. Transport Protocols: TCP and UDP

Overview

Transport protocols carry data between network endpoints. TCP provides an ordered reliable byte stream; UDP sends datagrams without the same delivery guarantees.

How It Works

HTTP/1.1 and HTTP/2 generally use TCP, while HTTP/3 uses QUIC over UDP.

Important Concept

The application protocol HTTP is different from the underlying transport protocol.

Try It Yourself

Sketch how HTTP, TLS, TCP, QUIC, and IP fit into the networking stack.

Key Takeaway

Transport protocols carry data between network endpoints. TCP provides an ordered reliable byte stream; UDP sends datagrams without the same delivery guarantees.

13. Introduction to HTTP

Overview

HTTP is an application-layer protocol for exchanging requests and responses between clients and servers.

How It Works

A request identifies a method and target; a response includes a status code and may include a body.

Important Concept

HTTP is stateless at the protocol level: each request is understandable without assuming application session state.

Try It Yourself

Inspect a network request and locate its method and response status.

Key Takeaway

HTTP is an application-layer protocol for exchanging requests and responses between clients and servers.

14. Anatomy of an HTTP Request

Overview

An HTTP request includes a method, target, headers, and sometimes a message body.

How It Works

Headers convey metadata such as Accept or Content-Type. POST requests often include a body.

Important Concept

A request body is not limited to POST, but its meaning depends on the method and server.

Example

GET /books HTTP/1.1
Host: example.com
Accept: text/html

Try It Yourself

Use Developer Tools to inspect request headers and payload.

Key Takeaway

An HTTP request includes a method, target, headers, and sometimes a message body.

15. Anatomy of an HTTP Response

Overview

An HTTP response includes a status code, headers, and usually a body containing content or data.

How It Works

Content-Type describes the media type, such as text/html or application/json.

Important Concept

A successful response may have no body, such as a 204 No Content response.

Example

HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8

<h1>Welcome</h1>

Try It Yourself

Inspect the response headers of an HTML page and an image.

Key Takeaway

An HTTP response includes a status code, headers, and usually a body containing content or data.

16. HTTP Methods: GET, POST, PUT, PATCH, DELETE

Overview

HTTP methods describe the intended action: GET retrieves, POST submits, PUT replaces, PATCH partially modifies, and DELETE requests removal.

How It Works

GET is defined as safe and idempotent; PUT and DELETE are idempotent by specification, while POST generally is not.

Important Concept

Method semantics matter for caching, retries, and API design.

Example

GET /api/books
POST /api/login
PATCH /api/profile
DELETE /api/bookmarks/12

Try It Yourself

Classify common website actions by HTTP method.

Key Takeaway

HTTP methods describe the intended action: GET retrieves, POST submits, PUT replaces, PATCH partially modifies, and DELETE requests removal.

17. Understanding HTTP Status Codes

Overview

Status codes report the outcome of a request. The first digit indicates the broad category.

How It Works

2xx means success, 3xx redirection, 4xx client-side error conditions, and 5xx server-side errors.

Important Concept

Common examples include 200 OK, 301 Moved Permanently, 404 Not Found, and 500 Internal Server Error.

Example

200 OK       — Request succeeded
301 Redirect — Resource moved permanently
404 Not Found — Resource not found
500 Error    — Server encountered an error

Try It Yourself

Find a 404 response in Developer Tools and inspect the requested URL.

Key Takeaway

Status codes report the outcome of a request. The first digit indicates the broad category.

18. Important HTTP Headers

Overview

Headers carry metadata that affects content negotiation, caching, authentication, and security.

How It Works

Content-Type identifies the response format; Accept states preferred formats; Location often accompanies redirects.

Important Concept

Header names are case-insensitive. Browser security policies also depend on specific headers.

Try It Yourself

Compare Content-Type for an HTML document, CSS file, and JSON response.

Key Takeaway

Headers carry metadata that affects content negotiation, caching, authentication, and security.

19. MIME Types and Browser Resource Handling

Overview

A MIME type identifies the kind of content being transferred, such as text/css or application/javascript.

How It Works

Browsers use content types and security rules to decide whether resources can be interpreted or executed.

Important Concept

A JavaScript URL returning an HTML error page can produce a MIME-type execution error.

Example

Content-Type: text/html
Content-Type: text/css
Content-Type: application/javascript
Content-Type: application/json

Try It Yourself

Inspect the Content-Type of a script request and check whether its URL returns JavaScript.

Key Takeaway

A MIME type identifies the kind of content being transferred, such as text/css or application/javascript.

20. How HTTPS and TLS Protect Connections

Overview

HTTPS is HTTP carried over an authenticated, encrypted transport using TLS.

How It Works

TLS helps protect data in transit from eavesdropping and tampering and authenticates the server certificate.

Important Concept

HTTPS does not guarantee that the website itself is trustworthy or that its application has no vulnerabilities.

Try It Yourself

Compare the scheme and connection information of HTTP and HTTPS pages.

Key Takeaway

HTTPS is HTTP carried over an authenticated, encrypted transport using TLS.

21. Digital Certificates and Certificate Authorities

Overview

A TLS certificate binds a server identity to a public key and is validated against trusted certificate authorities.

How It Works

Browsers check certificate validity, hostname coverage, and a chain of trust.

Important Concept

Expired, mismatched, or untrusted certificates can trigger browser warnings.

Try It Yourself

Inspect the certificate details of an HTTPS website.

Key Takeaway

A TLS certificate binds a server identity to a public key and is validated against trusted certificate authorities.

22. HTTP/1.1, HTTP/2, and HTTP/3

Overview

HTTP has evolved to improve efficiency while keeping the same core request–response semantics.

How It Works

HTTP/2 multiplexes streams over a connection; HTTP/3 uses QUIC to transport HTTP over UDP.

Important Concept

Different HTTP versions can serve the same URL and application content.

Try It Yourself

Find the protocol column in Developer Tools and inspect which version a request uses.

Key Takeaway

HTTP has evolved to improve efficiency while keeping the same core request–response semantics.

23. Cookies and Web Sessions

Overview

Cookies let servers ask browsers to store small pieces of state that can be sent with later requests.

How It Works

Session identifiers commonly associate requests with server-side login state.

Important Concept

Secure, HttpOnly, and SameSite attributes can reduce certain risks, but correct server-side session validation is still required.

Example

Set-Cookie: session=opaque-id; Secure; HttpOnly; SameSite=Lax

Try It Yourself

Inspect cookie attributes in browser developer tools without sharing their values.

Key Takeaway

Cookies let servers ask browsers to store small pieces of state that can be sent with later requests.

24. Browser Storage: Local Storage and Session Storage

Overview

Web Storage provides browser-managed key–value storage for same-origin web pages.

How It Works

localStorage usually persists across browser restarts; sessionStorage is scoped to a tab session.

Important Concept

Do not store passwords or sensitive session tokens in web storage when safer approaches are available.

Example

localStorage.setItem("readerTheme", "dark");
const theme = localStorage.getItem("readerTheme");

Try It Yourself

Store a harmless theme preference and observe whether it survives a reload.

Key Takeaway

Web Storage provides browser-managed key–value storage for same-origin web pages.

25. Browser Caching and Cache-Control

Overview

Caching can reuse previously fetched responses to reduce network requests and loading time.

How It Works

Cache-Control directives tell caches how to store or revalidate resources; ETag can support conditional requests.

Important Concept

A 304 Not Modified response indicates a cached representation can be reused after validation.

Example

Cache-Control: public, max-age=3600
ETag: "version-123"

Try It Yourself

Reload a page and look for cache-related headers or a 304 response.

Key Takeaway

Caching can reuse previously fetched responses to reduce network requests and loading time.

26. Same-Origin Policy and CORS

Overview

The same-origin policy limits how documents and scripts from different origins interact.

How It Works

An origin is defined by scheme, hostname, and port. CORS lets servers authorize certain cross-origin reads.

Important Concept

CORS is a browser access-control mechanism, not a replacement for authentication or authorization.

Try It Yourself

Compare two URLs and determine whether they have the same origin.

Key Takeaway

The same-origin policy limits how documents and scripts from different origins interact.

27. Web APIs and JSON Responses

Overview

A web API exposes endpoints that clients can call to exchange data or request operations.

How It Works

JSON is a common text format for structured API responses, and fetch() is a browser API for making requests.

Important Concept

Always check response.ok before assuming an API call succeeded.

Example

fetch("/api/books")
  .then(response => {
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    return response.json();
  })
  .then(data => console.log(data))
  .catch(error => console.error(error));

Try It Yourself

Inspect a JSON response in the Network panel.

Key Takeaway

A web API exposes endpoints that clients can call to exchange data or request operations.

28. Using Browser Developer Tools: Network Panel

Overview

The Network panel reveals requests, response statuses, headers, timings, transferred sizes, and resource types.

How It Works

It is useful for diagnosing missing files, slow requests, redirects, and unexpected server responses.

Important Concept

A 404 script request often means the path is wrong or the file was not deployed.

Try It Yourself

Open Developer Tools, reload the page, and filter requests by JS or CSS.

Key Takeaway

The Network panel reveals requests, response statuses, headers, timings, transferred sizes, and resource types.

29. Web Performance and Loading Optimization

Overview

Website performance depends on network latency, resource size, server responsiveness, and rendering work.

How It Works

Compression, caching, responsive images, deferred scripts, and smaller assets can improve loading.

Important Concept

Measure performance before and after optimization rather than relying only on intuition.

Try It Yourself

Compare transferred sizes and loading times for a page before and after an image optimization.

Key Takeaway

Website performance depends on network latency, resource size, server responsiveness, and rendering work.

30. Browser and Server Security Best Practices

Overview

Secure web applications validate input on the server, use HTTPS, manage sessions carefully, and keep dependencies updated.

How It Works

Security headers such as Content-Security-Policy can reduce certain injection risks; proper authorization checks remain essential.

Important Concept

Client-side validation improves usability but cannot replace server-side validation.

Try It Yourself

Review an example application for HTTPS, secure cookies, input validation, and safe error messages.

Key Takeaway

Secure web applications validate input on the server, use HTTPS, manage sessions carefully, and keep dependencies updated.
